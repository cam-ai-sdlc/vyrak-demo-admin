# ADR-001: Products page with React Router, shadcn/ui, Tailwind

## Status
Proposed

## Context
`vyrak-demo-admin` (Vite 8, React 19, TS 6) has Tailwind v4 (`@tailwindcss/vite` in `vite.config.ts`) and shadcn (`components.json`, style `base-maia`, Base UI, alias `@/components/ui`) already configured. Only `src/components/ui/button.tsx` exists. No router: `src/main.tsx` renders `<App />` in `ThemeProvider`. `react-router-dom` is not in `package.json`. A `/products` page is required.

## Decision
- Add `react-router-dom` (v7; it re-exports `react-router`) and use the data-router API: `createBrowserRouter` + `RouterProvider` in `src/main.tsx`.
- Route config lives in `src/router.tsx`; `App.tsx` becomes the root layout (`<Outlet />`).
- Feature code goes in `src/pages/products/` (page) and uses shadcn components added via CLI (`npx shadcn@latest add table card input badge skeleton`) into `src/components/ui/`.
- Style only with Tailwind utilities and theme tokens (`bg-background`, `text-muted-foreground`), using `cn` for class merging.
- Initial data: typed mock in `src/pages/products/data.ts`, exposed through a route `loader`, so a real API can replace it without changing the page.

## Alternatives
1. `<BrowserRouter>` + `<Routes>`: simpler, but there are no loaders and migrating later costs more.
2. TanStack Router: stronger type safety, but it isn't what was requested and adds a new concept.
3. Hand-rolled UI without shadcn: rejected; it duplicates the existing design system.

## Consequences
+ Consistent with the existing stack and theme (dark mode via `ThemeProvider`).
+ Loader pattern is ready for real APIs.
- New dependency. Some shadcn components may need Base UI-specific props (style `base-maia`), unlike Radix examples online.
- SPA fallback is needed in production hosting for deep links to `/products`. Vite dev and preview already handle it.

## Implementation Notes
See `plans/261119-0900-products-page/README.md`.
Note: `react-router-dom` works on v7 but is a re-export; importing from `react-router` is the upstream-preferred path. Keep `react-router-dom` as requested, and revisit if desired.
